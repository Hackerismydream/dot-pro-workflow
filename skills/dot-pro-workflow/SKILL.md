# dot 与 Pro 协作

由 dot 承担实施和验证，在有必要且已获授权时主动向 Pro 咨询，再推进到验收。
保持简单：不搭建额外平台，不让用户充当两个系统之间的传话人。

## 1. 明确任务

- 定位目标仓库，阅读适用的仓库指引，检查当前工作状态，保护用户已有修改。
- 明确目标、范围、验收标准、时间与额度上限，以及用户指定的 ChatGPT 项目。
- 复用本次任务已有授权；缺少会影响后续操作的信息时，只询问必要事项。
- 使用用户设定的额度上限、保留量和停止阈值；不得自行动用被保留的额度。
- 使用可获得的额度信息检查预算；无法确认时说明不确定性，不声称仍有额度。

## 2. 判断是否咨询

- 普通小 bug、局部清晰修改：直接实现并验证，不必每次咨询。
- 重大架构、跨模块规划、关键取舍或反复失败暴露设计问题：整理问题包咨询 Pro。
- 外部模型咨询及发送内容必须在用户授权范围内；本技能本身不构成授权。
- 问题包只含必要且获准分享的目标、现状、约束、候选方案、验收与具体问题。
- 用最小代码片段和脱敏的复现证据说明问题，不发送凭据、私密日志或原始会话。

## 3. 发起咨询并等待

- 通过现有授权的浏览器能力进入用户指定项目，核对项目及界面确已选中 Pro。
- 独立新问题开新会话；同一问题的澄清、实施结果与修订留在原会话。
- 发送前确认问题包，发送一次后记录会话位置与待答事项。
- 回复未完成时保持待答状态，异步等待并适度检查，不因等待而重复发送。
- 可继续不依赖该答复的已授权工作；依赖方案的工作等完整答复后再推进。
- 无法持续等待时保留状态并报告待答，不承诺永久后台运行。
- Pro 不可访问、选择无法确认或权限不足时，保留脱敏问题包并说明阻塞。
- 不冒称已咨询，不擅自改用其他模型；已获授权的小修仍可独立完成。

## 4. 审查并落地

- 将完整答复视为待审查建议：核对仓库事实、约束、可行性、风险和验收覆盖。
- 指出不成立的假设；按真实证据修正或在同一会话追问，不盲从 Pro。
- 在仓库适当文档位置保存简短、脱敏的方案摘要、采纳/拒绝理由和验证计划。
- 不复制私密会话全文；仅在可见性合适时保存咨询会话链接。
- 把采纳方案拆成小里程碑，逐步修改、调试、执行适用测试并检查实际结果。
- 测试失败先复现和定位，再修复与复测；设计性失败反馈证据，请 Pro 复审。
- 反馈只含必要的预期/实际差异、复现条件、已尝试修复和具体待决问题。

## 5. 持续推进与停止

- 向用户简短报告关键结果和阻塞，已授权且可执行的下一步继续推进。
- 合并、部署、付费及凭据操作遵守实际授权；模型方案不是执行命令或授权。
- 达到预算阈值、缺少必要权限、用户要求暂停或验收完成时，停止相应工作。
- 阻塞时保存当前修改、方案与待办，说明证据及恢复条件，不循环重试消耗额度。
- 完成时交付改动、验证结果、残余限制和可访问链接；不把未执行测试写成通过。
